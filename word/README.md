# 오골계 워드 1.0

HWP/HWPX 편집기(rhwp) + PDF 줄바꿈 복원 보기. 모든 처리가 이 컴퓨터 안에서만 일어납니다.

## 다운로드 및 실행

### Windows

1. [GitHub 릴리즈](https://github.com/OHgolgyeo/office/releases)에서 `Ogolgye-Word-Setup-<버전>.exe`를 받습니다.
2. 받은 설치 파일을 실행하면 설치 후 오골계 워드가 열립니다.
3. Windows에서 **PC 보호** 화면이 나오면 파일을 이 저장소의 공식 릴리즈에서 받았는지 확인한 뒤 **추가 정보 → 실행**을 누릅니다.

### macOS

1. [GitHub 릴리즈](https://github.com/OHgolgyeo/office/releases)에서 사용하는 Mac에 맞는 `.dmg`를 받습니다.
   - Apple Silicon(M1·M2·M3·M4 등): `mac-arm64.dmg`
   - Intel Mac: `mac-x64.dmg`
   - 칩 종류는 **Apple 메뉴() → 이 Mac에 관하여**에서 확인할 수 있습니다.
2. `.dmg`를 열고 **오골계 워드**를 **응용 프로그램** 폴더로 옮긴 뒤 실행합니다.
3. 개발자를 확인할 수 없다는 안내로 처음 실행이 막히면 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 누릅니다. 또는 Finder의 응용 프로그램 폴더에서 오골계 워드를 Control-클릭한 뒤 **열기**를 선택합니다.

서명되지 않은 첫 배포판이라 Windows SmartScreen이나 macOS Gatekeeper 안내가 나타날 수 있습니다. 설치 파일은 이 저장소의 공식 릴리즈에서만 받으세요.

## 개발용 실행

Node.js 20 이상이 필요합니다(`node -v`로 확인).

```bash
npm install          # Electron 과 필요한 라이브러리 설치
npm run get-model    # Kiwi 한국어 모델(약 88MB)과 그림 속 글자 읽기(OCR) 언어 자료(약 6MB) 받기 — 처음 한 번
npm start            # 오골계 워드 실행
```

`npm start`는 `scripts/start.js`로 Electron을 띄웁니다. 파일 열기 창의 PDF 썸네일 때문에 앱 안으로 들어온 알PDF 미리보기 부품이 찍는 `CheckLogLevel()∼∼GetHKCURegistryKeyAndValue failed.`만 터미널에서 지우고, 다른 출력은 그대로 보여 줍니다.

Electron 없이 브라우저로 확인하려면 `npm run serve`를 실행한 뒤 http://127.0.0.1:7801/app/ 을 엽니다.

## 배포와 자동 업데이트

설치한 앱은 켤 때와 켜 둔 동안 4시간마다 GitHub 릴리스([OHgolgyeo/office](https://github.com/OHgolgyeo/office/releases))를 확인합니다. 새 버전이 있으면 뒤에서 받아 두고 "지금 다시 시작 / 나중에"를 묻습니다. 나중에를 고르면 프로그램을 닫을 때 설치됩니다. 확인 기록은 `%APPDATA%\오골계 워드\update.log` 에 남습니다.

새 버전 내기:

1. `word/package.json`의 `version`을 올립니다(예: 1.0.0 → 1.0.1). **버전을 올리지 않으면 앱이 새 버전으로 알아보지 못합니다.**
2. 바뀐 파일과 함께 GitHub의 main에 올립니다.
3. 저장소의 GitHub Actions(`.github/workflows/word-release.yml`)가 Windows와 macOS 설치 파일을 만들어 `v<버전>` 릴리스로 올립니다. 이미 있는 버전이면 건너뜁니다. Actions 탭의 "Run workflow"로 직접 실행할 수도 있습니다.

직접 만들려면 `npm run dist`로 `dist/`에 설치 파일만 만들거나, `npm run release`로 GitHub 토큰(`GH_TOKEN`)을 사용해 릴리스까지 올릴 수 있습니다.

지켜야 할 것(자동 업데이트가 안 되는 흔한 원인):
- 릴리스는 **초안이 아니라 공개** 상태여야 합니다(설정: `releaseType: release`).
- 릴리스에 `latest.yml`, 설치 파일, `.blockmap`이 함께 있어야 합니다. 손으로 릴리스를 만들지 말고 위 방법으로 올립니다.
- 설치 파일 이름은 영문(`Ogolgye-Word-Setup-<버전>.exe`)으로 둡니다. 한글이나 띄어쓰기가 있으면 GitHub가 이름을 바꿔 `latest.yml`과 달라집니다.
- 사용자 자료(설정·PDF 주석·받은 OCR 언어)는 홈 폴더의 `.ogolgye-word`에 두므로 업데이트해도 남습니다. 프로그램 폴더에 저장하는 기능을 새로 만들지 않습니다.

## 화면

- 시작하면 빈 문서 하나가 열립니다. 새 문서·열기·저장은 편집 화면의 **파일** 메뉴를 사용합니다(Ctrl+S 등의 단축키도 편집 화면의 것을 사용합니다).
- 편집 화면 메뉴 줄의 **서브뷰** 메뉴(도구 옆)로 오른쪽에 하나 더 엽니다.
  - PDF 열기… → PDF 보기 창으로(글자 드래그·복사, 형광펜·북마크·포스트잇 메모, "문서화"로 편집 화면에 옮기기)
  - 문서 열기… / 새 문서 → 두 번째 편집기(그 편집기의 파일 메뉴로 따로 저장)
  - 서브뷰 닫기(또는 서브뷰 칸 오른쪽 위 ✕)
  - 파일을 서브뷰 칸에 끌어다 놓아도 됩니다(.pdf / .hwp / .hwpx).
- 가운데 분할바를 끌어 폭을 바꿉니다.

## PDF 여는 방식(빠르게)

- 앱을 켤 때 Kiwi 한국어 모델을 뒤에서 미리 불러 둡니다(PDF를 처음 열 때 기다리지 않도록 합니다).
- PDF를 열면 글자와 이미지 위치만 먼저 뽑아 **원본 보기가 바로** 뜹니다. 쪽 그림은 화면에 보이는 쪽만 그때그때 그립니다.
- 줄바꿈·문단 복원(Kiwi)은 뒤에서 처리하고, 끝나면 투명 글자 층(드래그·복사·형광펜)과 "문서화" 단추가 켜집니다.
- 그림 속 글자 데이터가 있으면(기울어진 카드의 글자 등) 같은 자리와 기울기에 투명한 글자를 겹쳐 드래그하거나 복사할 수 있습니다.
- 사진·스캔 PDF에서 글자 데이터가 없는 곳은 해당 쪽이 화면에 보일 때 로컬 OCR(Tesseract, Apache-2.0)로 읽습니다. 이때 쪽 오른쪽 아래에
  "그림 속 글자를 읽고 있습니다…"라고 표시합니다. 읽은 글자를 같은 자리와 기울기에 투명하게 겹쳐 드래그·복사·형광펜에 사용할 수 있습니다.
  "문서화"도 읽은 글자를 문단 단위로 옮깁니다(글자 데이터가 있는 본문과 섞인 쪽은 위에서 아래 순서로 끼워 넣고, 아직 읽지 않은 쪽은 문서화할 때 읽습니다).
  `도구 → 환경 설정 → OCR 언어`에서 한국어·영어 외 언어를 추가할 수 있다. 새 언어는 공식 `tessdata_fast` 자료를 한 번 내려받으며,
  이후 인식은 인터넷 없이 컴퓨터 안에서 처리합니다. 지도 선 위의 큰 글씨 등은 OCR이 놓칠 수 있습니다.
- "문서화"는 **글**(글만) 또는 **규칙 적용**으로 옮깁니다. 규칙은 `문서화 ▾ → 문서화 규칙`에서 고르며 설정 파일에 저장됩니다.
  - 오브젝트 이미지 가져오기: 내용 그림을 PDF에 그려진 크기로(글 폭·쪽 높이보다 크면 줄여서), "글자처럼 취급"으로 넣습니다.
    그림은 PDF에 든 원본 그대로 넣습니다(다른 그림 틀에 맞춰 잘려 있어도 원본 전체).
    표지처럼 쪽을 덮는 그림 위에 큰 제목이 얹힌 쪽, 기울어진 글씨가 얹힌 그림, 여러 조각으로 저장된 그림은 보이는 그대로 한 장의 그림으로 넣습니다.
    배경 그림(여러 쪽에 반복되는 그림, 쪽 머리 장식 띠, 본문이 빽빽이 얹힌 종이 질감), 글자 밑 바탕, 다른 그림에 가려진 그림(그림자)은 넣지 않습니다.
  - 표 모양 그대로 살리기: 선으로 그은 표를 칸 너비·합친 칸·칸 바탕색·글자색까지 한글 표로 넣습니다.
    그림 위에 본문이 얹힌 카드·상자는 1칸 표(바탕은 그림의 평균 색)로 넣습니다. 끄면 칸 글을 문단으로 넣습니다.
  - 레이아웃 분석(선 없는 표·스캔본·머리말/꼬리말): 선을 긋지 않은 표와 사진·스캔 쪽의 표를 찾아 한글 표로 넣고,
    쪽마다 되풀이되는 머리말·꼬리말(장 제목·쪽 번호·장식 띠)은 문서에 넣지 않습니다. PaddleOCR PP-Structure의
    레이아웃 인식(PP-DocLayoutV3)과 표 구조 인식(SLANet_plus) 모델을 ONNX Runtime으로 컴퓨터 안에서 돌립니다.
    칸 글자는 글자 정보가 있는 PDF면 PDF 글자 그대로, 스캔본이면 OCR로 채웁니다. 선으로 그은 표는 모델 없이 규칙으로 처리합니다.
    모델(약 131MB, Apache-2.0)은 설치 파일에 들어 있지 않고 처음 켤 때 `~/.ogolgye-word/models/pp-structure`로 한 번 내려받습니다.
    모델 실행 엔진이 애플 실리콘(arm64)용만 있어 인텔 맥에서는 쓸 수 없습니다.
  - 문단 사이 빈 줄 살리기: PDF에서 문단 사이가 한 줄 이상 비어 있던 곳에 그만큼 빈 줄(최대 3줄)을 넣습니다.
    끄면 본문이 끝나고 제목이 시작하는 곳에만 빈 줄 하나를 둡니다. 문단 간격(반 줄 정도)은 빈 줄로 보지 않습니다.
  - 목차는 "제목 + 오른쪽 탭(점선 채움) + 쪽 번호"로 넣어, 쪽 번호가 본문 오른쪽 끝에 맞춰집니다.
  - 여러 조각을 겹쳐 저장한 장식 그림은 한 장으로 합쳐 넣습니다.
  - 다단(2~4단) 본문은 단마다 위→아래로 읽고, 단 끝에서 다음 단으로 이어지는 문단은 하나로 붙입니다.
    단 아래에 일부 단 폭으로 놓인 글(설명·예시 상자 등)은 모든 단 다음에 읽고, 나란히 놓인 글끼리는 따로 둡니다.
    단 위·사이 가운데에 놓인 제목은 가운데 단의 첫 줄이 아니라 단을 가로지르는 제목으로 읽습니다.
- 서버 구조: `core/session.js`(열린 PDF 하나), `core/viewer-shell.js`(가벼운 보기 화면), `/pdf/<id>/…` 경로

## 테마

플랫 화이트 + 테마색 하나. 편집 화면의 **보기** 메뉴 맨 아래 "테마색"에서 10가지 중 고르거나 직접 고른다(기본: 올리브그린).
고른 색은 편집 화면·서브뷰·PDF 창에 한 번에 적용되고 설정 파일에 저장됩니다(Electron: 사용자 데이터 폴더의 settings.json).

## 편집 화면 꾸미기

로컬 서버가 편집 화면(rhwp-studio)을 내보낼 때 `renderer/studio-theme.css`와 `renderer/studio-bridge.js`를 끼워 넣습니다.
rhwp 소스는 건드리지 않으므로 rhwp를 새 버전으로 올려도 그대로 적용됩니다.

- `studio-theme.css`: 편집 화면의 `--ui-*`, `--color-*` 변수를 흰 바탕과 테마색(`--og-accent`)으로 덮어쓴다. 도구 막대 그라데이션·그림자 제거.
- `studio-bridge.js`: 주 문서 편집 화면의 메뉴 줄에 "서브뷰" 메뉴를, 보기 메뉴에 "테마색"을 넣고, 누르면 앱에 알립니다.

## 사용자 API 도구

`도구 → 환경 설정 → API 도구`에서 일반 로컬 HTTP API, Google Cloud REST API, OpenAI, Claude, Gemini, Vertex AI 및 OpenAI 호환 API를 등록할 수 있습니다.

- 등록한 도구는 서식 도구 줄의 **문단 정렬 오른쪽**에 각자 정한 이름·아이콘·색상으로 나타납니다.
- 도구마다 모델, API 주소, 기본 프롬프트, 플로팅 창/사이드 창, 사이드 창의 왼쪽·오른쪽 위치와 창 디자인 HTML을 따로 저장합니다.
- 사용자 지정/로컬 API에는 요청 JSON, 인증 헤더, 결과 위치를 정할 수 있습니다. 키가 필요 없는 localhost API도 사용할 수 있습니다.
- 문서에서 글을 선택하고 버튼을 누르면 선택 내용이 들어가며, 선택이 없으면 현재 페이지 목록 항목의 글을 가져옵니다. 결과를 복사하거나 선택한 본문을 결과로 바꿀 수 있습니다.
- API 키와 도구 설정은 Electron의 운영체제 보안 저장소로 암호화합니다. 키는 편집 화면으로 다시 보내거나 일반 설정 파일에 기록하지 않습니다.
- API를 실행하면 입력 내용이 사용자가 등록한 주소로 전송됩니다. 외부 API의 사용량과 비용은 해당 계정에 적용되며, 로컬 주소는 이 컴퓨터 안에서 호출됩니다. 브라우저 시험 모드에서는 보안 저장소가 없어 사용할 수 없습니다.

## 구조

| 파일 | 역할 |
|---|---|
| `main.js` | Electron 창, 파일 열기·저장 대화상자 |
| `preload.cjs` | 화면에 대화상자 기능만 열어 줌 |
| `server.js` | 127.0.0.1 로컬 서버: 편집 화면, 앱 화면, PDF 변환(`/api/pdf`), 빈 문서(`/api/blank`) |
| `renderer/` | 앱 화면(서브뷰, 분할바) + 편집 화면에 끼워 넣는 테마·메뉴(studio-theme.css, studio-bridge.js) |
| `core/` | PDF 복원 엔진(pdf-text-core 0.6.4 와 같음) |
| `vendor/rhwp-studio/` | rhwp 편집 화면(v0.8.6 + 오골계 워드 엔진 패치, 로컬 빌드, 외부 웹폰트 끔). `npm run build-engine` → `npm run build-studio` 로 다시 빌드 |
| `engine/patches/` | rhwp 편집 엔진(Rust)에 적용하는 오골계 워드 패치 |

편집 화면은 `file:` 주소에서 동작하지 않으므로(rhwp 제약) 앱 안에서 로컬 서버를 띄워 불러옵니다. 서버는 127.0.0.1에만 열리고 포트는 실행할 때마다 빈 포트를 고릅니다.

### 편집 엔진 패치(페이지 없음 보기)

페이지 없음 보기는 rhwp 엔진에 넣은 **보기 전용 용지**로 동작합니다(`engine/patches/rhwp-0.8.6-ogolgye.patch`).

- 문서의 용지 설정은 바꾸지 않습니다. 줄 나눔·쪽 나눔·그리기·위치 찾기만 창 폭 기준 용지를 쓰고, 쪽 설정(`getPageDef`)과 저장은 원래 용지를 씁니다.
- 한컴은 파일에 저장된 줄 나눔 정보를 믿고 조판하므로, 보기를 켜기 전의 원래 줄 나눔을 엔진 안에 보관했다가 저장할 때 그대로 기록합니다. 보기 중에 고친 문단만 원래 용지 폭으로 새로 나눕니다(바꾸지 않은 문서는 켜기 전과 같은 바이트로 저장된다).
- 되돌리기 기록은 하나이고, 창 폭이 바뀌어도 지워지지 않습니다.
- 함께 고친 rhwp 버그:
  - 용지 폭이 바뀐 뒤 줄 세로 위치(vpos)가 옛 용지 값으로 남아 쪽 나눔이 문단마다 새 쪽을 여는 문제(A4 26쪽 문서를 좁히면 33쪽이어야 할 것이 180쪽).
  - 문단 가운데에 책갈피를 넣거나 지우면 그 뒤 글자가 사라지는 문제.
  - 400KB가 넘는 HTML(한글 약 13만 자 이상)을 붙여 넣으면 문단 구분이 사라져 4000자씩 한 문단으로 뭉치는 문제.
  - 표 앞뒤에 문단이 있는 HTML(글·표·글)을 붙여 넣으면 엔진이 멈추는 문제(PDF 문서화의 표 모양 유지에 필요).
  - 붙여 넣은 HTML 표가 쪽 왼쪽 위에 떠서 본문과 겹치고, 칸 안 여백이 사라지고, 쪽 경계에서 나뉘지 않아 잘리는 문제.
- JavaScript API: `setViewPageDef(구역, 용지JSON)`, `clearViewPageDefs()`, `isViewLayoutActive()`.

## Google 문서로 보내기

`파일 → 다른 형식으로 내보내기 → Google 문서로 보내기`는 문서를 Word(.docx)로 만들어 본인의 Google 드라이브에 올리면서 Google 문서로 변환합니다. 오골계 워드에서 **페이지 없음**으로 보고 있던 문서는 Google 문서에서도 페이지 없음으로 열립니다. 이 기능을 쓸 때만 인터넷을 사용합니다.

처음 한 번, 본인의 Google Cloud 프로젝트에서 데스크톱 OAuth 클라이언트를 만들어 넣어야 합니다. 앱 안의 `도구 → 환경 설정 → Google 드라이브 연결`에도 같은 설명과 바로 가기 링크가 있습니다.

1. **프로젝트 준비** — [Google Cloud 콘솔](https://console.cloud.google.com/) 맨 위에서 기존 프로젝트를 고르거나 새 프로젝트를 만듭니다. 개인용이면 조직과 결제 정보는 필요하지 않습니다.
2. **API 사용 설정** — [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)와 [Google Docs API](https://console.cloud.google.com/apis/library/docs.googleapis.com)를 열고 각각 **사용**을 누릅니다.
3. **Google 인증 플랫폼 등록** — [Google 인증 플랫폼 개요](https://console.cloud.google.com/auth/overview)에서 **시작하기**를 누릅니다. 이미 개요가 보이면 이 단계는 끝난 것입니다.
   - 앱 이름: `오골계 워드`
   - 사용자 지원 이메일·연락처: 본인 이메일
   - 대상: 일반 Gmail은 **외부**. Google Workspace 조직 안에서만 쓸 때만 **내부**
   - 사용자 데이터 정책에 동의하고 **만들기**
4. **데이터 액세스 설정** — [데이터 액세스](https://console.cloud.google.com/auth/scopes) → **범위 추가 또는 삭제**에서 아래 두 범위를 체크하고 **업데이트 → 저장**합니다. 보이지 않으면 주소를 직접 추가합니다.
   - `https://www.googleapis.com/auth/drive.file` — 오골계 워드가 만든 파일 올리기
   - `https://www.googleapis.com/auth/drive.readonly` — 기존 드라이브 파일 목록 보기·받기
5. **테스트 사용자 추가** — [대상](https://console.cloud.google.com/auth/audience)의 게시 상태가 **테스트**라면 **테스트 사용자 → 사용자 추가**에 실제 로그인할 Google 계정을 넣습니다. 빠뜨리면 `access_denied`가 납니다.
6. **데스크톱 클라이언트 생성** — [클라이언트](https://console.cloud.google.com/auth/clients) → **클라이언트 만들기** → 유형 **데스크톱 앱** → 이름 `오골계 워드` → **만들기**. 생성된 `…apps.googleusercontent.com` 형식의 **클라이언트 ID**를 복사합니다. 데스크톱 앱의 보안 비밀은 OAuth에서 선택 사항이므로 오골계 워드에서도 비워 둘 수 있습니다.
7. **연결** — `도구 → 환경 설정 → Google 드라이브 연결`에 클라이언트 ID를 넣고 **저장 → 연결하기**. 테스트 사용자로 추가한 계정을 고르고 요청 권한을 허용합니다. 미확인 앱 화면이 나오면 본인이 만든 클라이언트인지 확인한 뒤 **고급 → 오골계 워드(으)로 이동**으로 진행합니다.

- 요청하는 권한은 두 가지입니다. `drive.file`(오골계 워드가 만든 파일 올리기)과 `drive.readonly`(드라이브의 파일 목록 보기·받기, **읽기 전용**). 드라이브의 파일을 고치거나 지우지 않습니다.
- 로그인은 기본 브라우저에서 하므로 오골계 워드는 비밀번호를 보지 않습니다(루프백 주소 + PKCE).
- 연결 정보는 운영체제의 보안 저장소(Electron safeStorage)로 암호화해 사용자 데이터 폴더에 둡니다. 보안 저장소를 사용할 수 없는 환경에서는 평문으로 대신 저장하지 않고 Google 연결을 중단합니다. `연결 끊기`를 누르면 Google 에 토큰 폐기를 요청하고 이 컴퓨터에서도 지웁니다.

`drive.readonly`는 드라이브 전체의 파일을 읽고 내려받을 수 있는 Google의 **제한된 범위**입니다. 오골계 워드는 사용자가 고른 파일을 열 때만 사용하고 파일을 수정하거나 삭제하지 않지만, 권한 화면에는 넓은 읽기 권한으로 표시됩니다.

### 7일마다 다시 연결하지 않으려면

Google 정책상 외부 앱이 **테스트** 상태이면 오프라인 연결용 갱신 토큰도 7일 뒤 만료됩니다. [대상](https://console.cloud.google.com/auth/audience)에서 **앱 게시**를 눌러 프로덕션으로 바꾼 뒤 오골계 워드에서 다시 연결하면 이 7일 제한이 없어집니다. 본인 또는 직접 아는 소수만 사용하는 개인용 앱은 미확인 경고와 100명 한도 안에서 검증 예외를 적용받을 수 있습니다. 불특정 사용자에게 배포하려면 `drive.readonly` 제한 범위에 대한 Google 검증이 필요합니다.

## Google 드라이브에서 열기

`파일 → Google 드라이브에서 열기`에서 내 드라이브·공유 문서함의 파일을 폴더별로 보거나 이름으로 찾아 열 수 있습니다.

| 파일 | 여는 방법 |
|---|---|
| 한글(HWP·HWPX) | 원본 그대로 편집 화면 또는 서브뷰에서 엽니다 |
| PDF | 서브뷰(PDF 창)로 엽니다. 드래그 복사·문서화·그림 끌어다 놓기를 그대로 쓸 수 있습니다 |
| Word(.docx) | 글자 모양·정렬·제목·표(합친 칸 포함)·그림을 한글 문서로 바꿔 엽니다 |
| Google 문서 | Google Docs API로 탭·본문·서식·그림을 직접 받아 한글 문서로 바꿔 엽니다. **페이지 / 페이지 없음** 보기 방식도 그대로 따릅니다 |

- Word·Google 문서는 편집 화면에 붙여넣지 않고 한글 엔진으로 문서를 직접 만듭니다(표가 든 붙여넣기의 엔진 버그를 피하기 위해).
- 예전에 보내기 권한만으로 연결했다면, 가져오기를 쓰기 전에 환경 설정 → Google 드라이브 연결에서 **연결하기**를 한 번 더 누르세요(읽기 권한 추가).

## 서식(Google 문서식 스타일)

도구 막대의 스타일 목록은 Google 문서와 같은 **일반 텍스트 / 제목 / 부제목 / 제목 1~6**을 보여 줍니다. 각 스타일은 실제 한글 스타일로 문서에 들어가므로 한컴에서 열어도 같은 이름으로 보입니다.

| 스타일 | 크기·색 | 단축키 |
|---|---|---|
| 일반 텍스트 | 11pt | Ctrl+Alt+0 |
| 제목 / 부제목 | 26pt / 15pt 회색 | |
| 제목 1 ~ 6 | 20·16·14·12·11·11pt(4~6은 회색, 6은 기울임) | Ctrl+Alt+1 ~ 6 |

- 새 문서는 일반 텍스트로 시작합니다. 제목·부제목 **끝에서** 엔터를 치면 다음 문단은 일반 텍스트가 됩니다(가운데에서 나누면 두 문단 모두 제목).
- 한글 파일에 원래 있던 스타일(바탕글, 개요 1 …)은 지우지 않고, 목록 아래 "한글 스타일"에 모아 둡니다.
- 내보내기(Word·ODT·RTF·EPUB·Markdown)는 이 스타일을 각 형식의 제목 구조로 옮기고, Word·Google 문서를 가져올 때는 제목·부제목·제목 1~6을 같은 스타일로 받습니다(제목 안에 직접 입힌 서식은 유지).

## 페이지 목록

서식 도구 줄 맨 왼쪽의 **페이지 목록** 버튼(일반 텍스트 스타일 목록 앞)에서 Google 문서처럼 문서를 여러 페이지 목록으로 나눌 수 있습니다. 버튼을 열면 페이지 목록과 선택한 페이지의 제목 목차가 나옵니다.

- **＋**: 새 페이지 추가(새 페이지는 새 쪽에서 시작합니다). 페이지에 마우스를 올리면 나오는 **⋮**에서 이름 바꾸기·페이지 삭제.
- 탭을 누르면 **그 탭의 내용만** 보입니다(페이지 없음·용지 모두). 방향키로 탭 끝을 넘어가면 다음 탭으로 넘어갑니다.
- 고른 탭 아래에는 그 탭의 제목(제목, 제목 1~6) 목차가 나오고, 누르면 그 자리로 이동합니다.
- 탭은 한글 파일 안에 "쪽 나누기 + 탭 이름 책갈피(`오골계워드:탭=이름`)"로 저장됩니다. 한컴에서 열면 탭마다 새 쪽에서 시작하는 한 문서로 보입니다.
- 탭 추가·이름 바꾸기·삭제는 실행 취소(Ctrl+Z)로 되돌릴 수 있습니다.
- 서브뷰로 연 문서는 탭 구분 없이 전체를 보여 줍니다.
- 아직 **탭 순서 바꾸기는 없습니다**(한글 엔진의 내용 옮기기 기능에 버그가 있어 안전하게 만들 수 없었습니다).

### Google 드라이브와 탭

- **가져오기**: 탭이 있는 Google 문서를 열면 탭(하위 탭 포함)이 그대로 오골계 워드 탭이 됩니다. Google 문서 API 로 내용을 직접 받아 제목 스타일·글자 모양·정렬·표(합친 칸)·그림을 탭별로 옮기고, 보기 방식(페이지 / 페이지 없음)도 따릅니다.
- **보내기**: 탭이 둘 이상인 문서를 Google 문서로 보내면, 첫 탭은 Word 로 올려 변환하고 둘째 탭부터는 Google 문서에 탭을 만들어 내용(스타일·글자 모양·정렬·표)을 채웁니다. 페이지 없음이면 모든 탭을 페이지 없음으로 바꿉니다.
- **둘째 탭부터의 그림은 보내지 못합니다.** Google 문서 API 는 인터넷에 공개된 주소의 그림만 넣을 수 있어, 그림을 공개하지 않는 한 옮길 방법이 없습니다. 이 경우 몇 개를 옮기지 못했는지 알려 줍니다.
